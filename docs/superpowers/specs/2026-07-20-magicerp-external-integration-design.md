# MagicERP 외부 월별 매출 연동 설계

## 목표

관리 페이지의 `외부 연동` 탭에서 MagicERP 월별 매출을 조회하고, 기존 PNP 기록과의 충돌을 관리자가 검토·승인한 뒤 매출 분석에 반영한다.

## 범위

- MagicERP 로그인, 월별 메뉴, 매장 선택, 연도별 조회를 서버의 헤드리스 Chromium으로 자동화한다.
- 조회 결과를 승인 전 미리보기로 표시한다.
- 승인된 외부 월별 매출만 PNP 매출 분석에 포함한다.
- 연·월·매장 기준으로 기존 PNP 일일 운영 기록과 비교해 충돌 여부와 금액 차이를 표시한다.

이번 범위에는 주기 자동 동기화, MagicERP 계정 저장, 일별/상품별 세부 매출 가져오기, 기존 PNP 일일 기록의 수정·삭제를 포함하지 않는다.

## 확인된 MagicERP 흐름

2026-07-20에 제공된 계정으로 헤드리스 Chromium 로그인과 화면 구조를 확인했다.

1. `https://smart.magicerp.co.kr/member/login.asp`에서 `id`, `pw`를 POST로 로그인한다.
2. 로그인 뒤 `https://smart.magicerp.co.kr/main.asp`에서 `월별` 메뉴를 선택한다.
3. 월별 화면은 `https://smart.magicerp.co.kr/magicerp/monthly.asp`이며, 조회 연도와 브랜드, 매장 사용 여부, 매장 선택 필드를 제공한다.
4. 매장 선택 다이얼로그는 광화문점, 방이점, 여의도점, 연희점, 연희점 카페, 잠실점을 제공한다. 각 항목은 MagicERP 내부 매장 ID를 갖는다.

실제 런타임 구현은 화면 텍스트와 DOM 구조를 검증하고, 변경되었거나 결과를 읽을 수 없으면 반영을 중단하고 재시도 가능한 오류를 반환한다.

## 사용자 흐름

1. 관리자가 `관리 > 외부 연동` 탭을 연다.
2. MagicERP ID와 비밀번호, 조회 연도, 매장을 입력한다.
3. `월별 데이터 불러오기`를 누르면 버튼을 비활성화하고 진행 상태를 표시한다.
4. API가 MagicERP에 로그인해 월별 결과를 가져오고, 월별 매출·건수와 기존 PNP 월 집계를 나란히 보여 준다.
5. 각 월에 대해 다음을 표시한다.
   - MagicERP 매출과 건수
   - PNP 일일 운영 기록의 매출과 건수
   - 차이 금액 및 차이 건수
   - PNP 기록이 존재하는 경우 `중복 가능` 충돌 표시
6. 관리자는 충돌 월을 포함해 반영할 월을 선택한다. 반영 대상이 충돌하면 확인 문구가 있는 승인 단계가 필요하다.
7. `승인 후 반영`을 누르면 선택된 월의 외부 월별 매출을 저장하고 매출 분석을 갱신한다.
8. 이미 승인된 동일 연·월·매장을 다시 승인하려면 교체 확인을 요구한다. 교체 전 값은 삭제하지 않고 이력으로 남긴다.

## 아키텍처

### 웹

- `ManagementPage`에 `external-integration` 탭을 추가한다.
- 연동 폼, 미리보기 표, 충돌 요약, 승인 확인 대화상자를 별도 컴포넌트로 분리한다.
- 비밀번호 입력에는 `type=password`, 표시/숨김 제어, 자동완성 힌트를 제공한다. 입력 값은 요청 완료·실패 후 즉시 메모리에서 비운다.
- 모든 아이콘 버튼에는 레이블을 제공하고, 로딩·오류는 `aria-live`로 알린다.

### API

- `POST /api/v1/external-integrations/magicerp/monthly/preview`: 요청 본문의 자격증명, 연도, MagicERP 매장 ID를 사용해 월별 데이터를 조회하고 PNP 집계와 충돌 정보를 반환한다. 자격증명은 요청 범위에서만 사용한다.
- `POST /api/v1/external-integrations/magicerp/monthly/approve`: 미리보기에서 사용자가 선택한 월별 값을 승인·저장한다. 서버는 저장 직전에 동일 연·월·매장 충돌을 다시 확인한다.
- 브라우저 자동화는 `MagicErpMonthlyClient` 인터페이스 뒤에 둔다. 라우트는 이 인터페이스만 사용하므로 테스트에서 네트워크 없이 대체할 수 있다.
- Chromium 프로세스와 MagicERP 쿠키 컨텍스트는 요청 완료·실패·시간 초과 시 모두 종료한다.

### 데이터와 집계

- `ExternalMonthlySales` 저장소는 공급자(`MAGICERP`), MagicERP 매장 ID·이름, 연·월, 매출액, 거래 건수, 승인 상태, 승인 시각, 대체 대상 및 생성 시각을 보관한다.
- 동일 공급자·매장·연·월에는 현재 승인된 값 하나만 유지한다. 재승인은 새 레코드를 만들고 이전 레코드를 대체됨 상태로 전환한다.
- 매출 분석은 PNP 일일 운영 기록의 월 합계와 현재 승인된 외부 월별 값을 각각 제공한다. 둘 모두 존재하는 달은 합산하지 않고 충돌 상태와 별도 출처 금액을 제공한다.
- 화면에서 관리자가 승인한 충돌 월은 외부 월별 값이 해당 월의 분석용 매출·건수 기준값이 된다. 비충돌 월도 외부 값이 기준값이 된다. 일일 추세는 기존 PNP 일일 운영 기록만 유지하며, 외부 월별 총액을 임의로 일자에 분배하지 않는다.

## 오류 처리

- 잘못된 로그인 정보, MagicERP 접근 실패, 선택한 매장 부재, DOM/결과 형식 변경, 타임아웃은 반영 없이 명확한 복구 안내와 재시도 버튼을 표시한다.
- 브라우저 자동화 오류와 감사 로그에는 ID, 비밀번호, 쿠키, 세션 URL의 민감한 쿼리 값을 기록하지 않는다.
- 승인 요청의 데이터가 미리보기와 달라졌거나 동시 승인으로 최신 상태가 바뀌면 승인을 거부하고 새 미리보기를 요청한다.

## 보안 및 구성

- 실제 운영에서 MagicERP ID와 비밀번호는 매 요청의 웹 폼에서만 받는다. DB, 서버 환경 변수, 브라우저 저장소, 감사 로그에 저장하지 않는다.
- 현재 `.env`의 `pos_id`, `pos_pw`는 개발 환경에서 대상 시스템을 확인하기 위한 값이며, 런타임 연동의 폴백으로 사용하지 않는다.
- API는 기존 관리 권한 경계를 따른다. 향후 역할 기반 권한이 추가되면 외부 연동의 조회·승인 권한은 OWNER에 제한한다.

## 테스트와 완료 기준

- MagicERP 클라이언트 단위 테스트: 로그인·매장 목록·월별 결과 파싱·구조 변경·인증 실패·시간 초과.
- API 테스트: 미리보기 충돌 계산, 승인 저장, 재승인 대체, 동시성/미리보기 불일치 거부, 비밀값 비노출.
- 매출 분석 테스트: 외부 값만 있는 월, PNP 값만 있는 월, 충돌 월에서 외부 승인값 우선, 일별 추세 보존.
- 웹 테스트: 필수 입력 검증, 로딩/오류 상태, 충돌 배지, 선택 승인, 확인 대화상자, 요청 완료 후 비밀번호 초기화.
- 수동 확인: 375px와 데스크톱에서 키보드 조작, 포커스, 44px 이상의 주요 터치 대상, 색 외 텍스트로 표시되는 충돌 상태를 확인한다.
