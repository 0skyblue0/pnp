# 선결제장부 재설계 실행 계획

> **For Hermes:** 선결제장부는 직원이 손님을 빠르게 찾고, 충전/사용/되돌리기를 실수 없이 처리하는 계산대용 화면으로 재설계한다.

**Goal:** 선결제장부를 ‘복잡한 상세 내역 표’가 아니라 ‘손님 선택 → 현재 잔액 확인 → 충전/사용 처리 → 최근 흐름 확인’이 한눈에 들어오는 화면으로 바꾼다.

**Architecture:** 기존 API(`/api/v1/prepaid-ledger`)와 DB 구조는 유지하고, 우선 프론트엔드 레이아웃/상호작용을 대폭 개선한다. 기능 추가가 필요한 경우에도 기존 `PrepaidCustomer`, `PrepaidTransaction` 모델을 확장하기보다 현재 note/transaction 데이터를 더 잘 보여주는 방식부터 적용한다.

**Tech Stack:** React, TypeScript, Tailwind, existing API client, existing PrepaidLedgerPage.

---

## 현재 문제

- 손님 목록과 상세 기능이 한 화면에 많아 직원이 어디부터 봐야 할지 어렵다.
- 상세내역에서 충전/사용/되돌리기/메모가 한 덩어리로 보여 복잡하다.
- ‘상세 기능 열기’ 구조가 장부 흐름을 숨겨서 직관성이 떨어진다.
- 최근 내역이 금액 중심으로만 보여서 잔액 변화 흐름이 눈에 잘 안 들어온다.
- 직원 입장에서 가장 중요한 행동인 `사용 처리`와 `추가 충전`이 충분히 크고 명확하지 않다.

## 목표 UX

1. 상단: 손님 검색 + 신규 등록 + 총 잔액 요약.
2. 왼쪽: 손님 리스트. 이름, 연락처, 잔액, 최근 사용일을 compact card로 표시.
3. 오른쪽: 선택한 손님의 큰 상세 패널.
4. 상세 패널 상단: 이름/연락처/현재 잔액/최근 사용일.
5. 상세 패널 중앙: 가장 자주 쓰는 `사용 차감`과 `추가 충전`을 큰 버튼형 카드로 분리.
6. 상세 패널 하단: 거래내역을 타임라인으로 정리하고, 되돌리기는 각 거래 오른쪽에 작게 배치.
7. 메모는 별도 작은 카드로 분리해서 거래내역과 섞이지 않게 한다.

## Task 1: 선결제장부 화면 구조 재배치

**Objective:** 기존 표 중심 레이아웃을 좌측 손님 리스트 + 우측 상세 패널 구조로 바꾼다.

**Files:**
- Modify: `apps/web/src/modules/prepaid-ledger/PrepaidLedgerPage.tsx`
- Test: `apps/web/src/app/App.test.tsx`

**Steps:**
1. 기존 상단 요약은 유지하되 더 작게 정리한다.
2. `sortedCustomers`를 왼쪽 `손님 목록` 카드로 렌더링한다.
3. 각 손님 카드는 `손님명`, `연락처`, `잔액`, `최근 거래`만 보여준다.
4. 선택 상태를 시각적으로 강조한다.
5. 오른쪽에는 `selectedCustomer` 상세 패널만 보여준다.
6. 고객이 없으면 오른쪽에 `손님을 선택하거나 신규 등록하세요` 빈 상태를 보여준다.

**Verification:**
- `선결제 장부` 탭에서 손님 목록과 상세 패널이 2단 구조로 보인다.
- 클릭한 손님만 오른쪽 상세가 바뀐다.

## Task 2: 상세 패널을 핵심 행동 중심으로 단순화

**Objective:** 사용/충전/메모/내역을 시각적으로 분리해 한눈에 들어오게 한다.

**Files:**
- Modify: `apps/web/src/modules/prepaid-ledger/PrepaidLedgerPage.tsx`

**Steps:**
1. 상세 패널 맨 위에 큰 잔액 박스를 둔다.
2. `사용 차감`을 왼쪽 또는 상단 첫 번째 큰 액션 카드로 둔다.
3. `추가 충전`은 별도 큰 액션 카드로 둔다.
4. 두 액션 카드 모두 금액 입력 + 메모 입력 + 실행 버튼만 포함한다.
5. `기타 메모`는 접힌 영역이나 하단 작은 카드로 분리한다.
6. 기존 `등록·충전·사용 상세 기능 열기` details 구조는 제거한다.

**Verification:**
- 상세를 열었을 때 사용/충전 입력이 바로 보인다.
- 거래내역과 메모가 액션 입력과 섞이지 않는다.

## Task 3: 거래내역을 타임라인으로 재설계

**Objective:** 상세내역을 직원이 빠르게 이해하도록 날짜별/행동별 타임라인으로 정리한다.

**Files:**
- Modify: `apps/web/src/modules/prepaid-ledger/PrepaidLedgerPage.tsx`

**Steps:**
1. 각 거래를 `충전 +50,000원` 또는 `사용 -5,000원` 형태로 크게 표시한다.
2. 날짜는 좌측 또는 상단에 작게 표시한다.
3. 거래 메모는 금액 아래 한 줄로 표시한다.
4. 되돌리기는 빨간 큰 버튼이 아니라 작은 `되돌리기` 텍스트 버튼으로 유지한다.
5. 최근 5건 기본 표시 + `전체 내역 보기`는 유지한다.
6. 가능하면 `거래 후 잔액` 계산값을 프론트에서 역산해 표시한다. 단, 거래 정렬과 현재 잔액 기준이 불확실하면 이 기능은 후순위로 둔다.

**Verification:**
- 상세내역이 표처럼 보이지 않고 시간순 카드/타임라인으로 보인다.
- 충전과 사용이 색/부호로 명확히 구분된다.

## Task 4: 신규 등록을 화면 하단에서 상단/별도 패널로 이동

**Objective:** 신규 등록 폼이 상세내역과 섞이지 않도록 한다.

**Files:**
- Modify: `apps/web/src/modules/prepaid-ledger/PrepaidLedgerPage.tsx`

**Steps:**
1. `신규 등록` 버튼을 누르면 상단 또는 오른쪽 패널 안에서 신규 등록 모드가 열린다.
2. 신규 등록 모드에서는 손님 이름/연락처/선결제 금액/메모만 보인다.
3. 저장 후 새 손님이 선택되고 상세 패널로 이동한다.
4. 기존 신규 등록 폼이 항상 보이지 않게 한다.

**Verification:**
- 신규 등록 버튼을 눌렀을 때만 등록 폼이 보인다.
- 저장 후 등록 손님이 선택된다.

## Task 5: 빠른 사용 금액 버튼 추가

**Objective:** 계산대에서 자주 쓰는 금액 입력을 빠르게 만든다.

**Files:**

2. 기본 버튼: `5,000`, `10,000`, `20,000`, `50,000`.
3. 클릭 시 사용 금액 입력칸에 해당 금액을 채운다.
4. 기존 직접 입력은 유지한다.

**Verification:**
- 빠른 금액 버튼 클릭 시 입력값이 채워진다.

## Risks / Tradeoffs

- 이번 재설계는 먼저 UI/UX 중심으로 진행한다. DB 변경 없이도 충분히 좋아질 수 있다.
- `거래 후 잔액`은 거래 정렬/취소 내역 처리 기준이 명확해야 하므로 첫 버전에서는 생략하거나 조심스럽게 계산한다.
- 너무 많은 빠른 기능을 넣으면 다시 복잡해질 수 있으므로, 1차 목표는 `손님 찾기`, `현재 잔액`, `사용`, `충전`, `최근 내역`만 선명하게 만드는 것이다.

## Acceptance Criteria

- 직원이 손님을 검색하고 선택하는 데 1~2초 이상 고민하지 않는다.
- 선택한 손님의 현재 잔액이 화면에서 가장 잘 보인다.
- 사용/충전 입력 위치가 명확히 분리된다.
- 상세내역이 표가 아니라 거래 흐름으로 읽힌다.
- 되돌리기는 가능하지만 과하게 눈에 띄지 않는다.
- 신규 등록은 필요할 때만 열리고 기본 화면을 어지럽히지 않는다.
