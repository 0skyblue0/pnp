# 일일 운영 엑셀 동일 구조 미리보기 설계

## 목적

엑셀 불러오기에서 저장 전 파싱 결과를 기존 `데이터 조회 > 조회된 일지`와 같은 정보 구조와 상세 표현으로 검토하게 한다. 사용자는 저장된 기록을 보듯 매출, 제품, 메모, 근무·점검 정보를 확인하고, 검증 경고가 있는 날짜만 명시적으로 승인한다.

## 범위

- 엑셀 미리보기 결과를 `DailyOperationSavedRecord` 형태로 변환한다.
- 조회 결과의 일지 카드·상세·제품 요약/상세 UI를 공용 읽기 컴포넌트로 추출한다.
- 기존 조회는 수정/삭제 가능한 상태를 유지한다.
- 엑셀 미리보기는 읽기 전용 상태이며 수정/삭제 버튼을 표시하지 않는다.
- 기존의 날짜별 검증 경고 확인과 저장 차단을 공용 카드에 함께 표시한다.

## 화면 구조

1. 파일을 선택하면 파싱이 끝난 뒤 `엑셀 미리보기 일지` 영역을 표시한다.
2. 이 영역은 조회 결과와 같은 요약 지표(총매출, 일 평균 매출, 객단가, 제품 판매량)를 표시한다.
3. 날짜별 카드의 한 줄 요약, `상세/접기`, 상세 지표, 메모 원문, 기본·점검, 제품 요약/상세 표는 조회된 일지와 동일하게 렌더링한다.
4. 각 경고 날짜에는 불일치 필드와 엑셀값/계산값을 표시하고, 해당 날짜 확인 체크박스를 바로 아래에 둔다.
5. 하나라도 확인되지 않은 경고 날짜가 있으면 저장 버튼은 비활성화된다.

## 컴포넌트 경계

- `DailyRecordResults`: `records`, `title`, `readOnly`, `warningByDate`, `acknowledgedDates`, `onAcknowledgementChange`를 받아 일지 요약·상세를 렌더링한다.
- `DailyLookupSection`: 조회 필터·비교 지표를 유지하고 공용 결과 컴포넌트를 `readOnly=false`로 사용한다.
- `DailyOperationExcelImportPanel`: 미리보기 API 응답을 저장 레코드로 변환하고 공용 결과 컴포넌트를 `readOnly=true`로 사용한다.

## 접근성·반응형 기준

- 기존 버튼의 텍스트 라벨과 `aria-label`을 보존한다.
- 경고는 색상 외에도 `검증 경고` 텍스트와 수치로 전달한다.
- 체크박스는 날짜와 승인 의미가 포함된 레이블을 가진다.
- 조회 카드와 동일한 CSS grid를 사용하되, 작은 화면에서는 카드 열이 한 열 또는 두 열로 재배치되어 가로 스크롤을 만들지 않는다.
- 비활성 저장 버튼은 `disabled` 속성과 시각적 비활성 상태를 함께 사용한다.

## 검증

- UI 테스트에서 엑셀 미리보기의 한 줄 요약과 상세 펼침이 조회 카드와 같은 레이블을 노출하는지 확인한다.
- 경고 날짜는 확인 전 저장할 수 없고, 확인 후 `acknowledgedDates`가 API로 전달되는지 확인한다.
- 기존 조회 UI 테스트가 수정/삭제 동작을 계속 보장한다.
