# 매출 분석 탭 개선 계획

> **For Hermes:** Use subagent-driven-development skill to implement this plan task-by-task.

**Goal:** 현재 매출 분석 탭을 “숫자 나열 화면”에서 “사장/직원이 바로 판단할 수 있는 매출 현황판”으로 개선한다.

**Architecture:** 기존 `/api/v1/sales-analysis/summary?year=YYYY`와 `DailyOperationRecord` 기반 집계를 유지하되, API가 화면 판단에 필요한 파생 지표를 더 명확히 내려주고, 웹은 첫 화면을 요약/신호/그래프/상세 순서로 재구성한다. 목표 금액이 없을 때는 `0%`가 아니라 “목표 미설정”으로 표시하고, 목표 입력 위치로 연결한다.

**Tech Stack:** Fastify + Prisma API, React + Vite web, Vitest/Testing Library.

## 2. 문제점

### 문제 1: 목표가 없는데 `목표 달성률 0%`로 보여서 오해된다

현재 API는 목표 금액이 없으면 `targetProgressRate: null`을 내려준다. 하지만 웹의 `percent()`가 `null`을 `0%`로 변환한다.

결과:
- 실제로는 목표가 설정되지 않은 상태인데, 화면은 목표 달성률이 0%인 것처럼 보인다.
- 월별 그래프도 모든 월에 `목표 0%`가 반복되어 화면 신뢰도가 떨어진다.

개선 방향:
- 목표가 없으면 `목표 미설정`으로 표시한다.
- 월별 목표도 `목표 없음` 또는 아예 숨긴다.
- 가능하면 `관리 > 홈 공지/매출 목표`로 이동하는 안내 버튼을 추가한다.

### 문제 2: 첫 화면이 “그래서 좋은가/나쁜가”를 말해주지 않는다

현재 KPI는 숫자를 보여주지만 해석이 없다.

부족한 질문:
- 이번 달이 지난 달보다 늘었나 줄었나?
- 객단가는 좋아졌나?
- POS 외 매출 비중은 얼마나 되나?
- 손실이 매출에 비해 심한 제품은 무엇인가?
- 지금 사장이 먼저 봐야 할 신호는 무엇인가?

개선 방향:
- 첫 카드에 `현장 요약` 한 줄을 추가한다.
- 예: `2026년은 5~6월 기록 기준 134,796,610원입니다. 6월은 5월보다 4,610,990원 낮습니다.`
- 목표가 있으면 목표 대비 문장, 없으면 목표 미설정 문장을 보여준다.

### 문제 3: 월별 그래프가 매출 없는 달도 같은 무게로 보여서 시선이 분산된다

현재 1~4월, 7~12월도 작은 점처럼 표시된다. 실제 데이터는 5월/6월뿐인데, 화면은 12개월 전체가 같은 정보량처럼 보인다.

개선 방향:
- 데이터 없는 달은 `기록 없음`으로 옅게 표시한다.
- 매출 있는 월만 강조한다.
- 월별 막대 안/옆에 `건수`, `객단가`, `전월 대비`를 추가한다.
- 전월 데이터가 있을 때 `전월 대비 +/− 금액`, `%`를 표시한다.

### 문제 4: 하단 카드들이 단순 리스트라 의사결정으로 이어지지 않는다

현재:
- 채널별 매출: 금액과 건수만 표시
- 많이 팔린 제품: 판매 개수만 표시
- 손실 제품: 손실 개수만 표시

문제:
- 채널별 비중이 눈에 잘 안 들어온다.
- 제품 판매는 매출 기여인지 단순 수량인지 구분이 어렵다.
- 손실은 손실률이 없어 심각도를 판단하기 어렵다. 예를 들어 판매량이 많은 제품의 손실 20개와 판매량이 적은 제품의 손실 15개는 의미가 다르다.

개선 방향:
- 채널별 매출에 비중 바를 추가한다.
- 제품 TOP에는 판매 수량 + 시식 수량 + 손실 수량을 함께 표시한다.
- 손실 TOP에는 `손실률 = 손실 / (판매 + 손실 + 시식)`을 추가한다.
- 손실률이 높은 제품을 별도 카드로 보여준다.

### 문제 5: POS 외 채널 이름/제품 이름 정리가 분석 품질에 영향을 준다

현재 실제 데이터에 `허 브`처럼 띄어쓰기 이상 제품명이 보인다. 채널도 `배민`, `쿠팡이츠`, `제로페이`, `납품`, `선물`, `택배`가 그대로 집계된다.

문제:
- 제품명 오타/띄어쓰기 차이가 있으면 판매 순위가 쪼개질 수 있다.
- 채널 이름이 운영 기준과 맞는지 불명확하면 월별 비교가 흔들린다.

개선 방향:
- 매출 분석 API에서 제품/채널 원문을 그대로 쓰되, 관리 제품명과 매칭되지 않는 이름을 `데이터 정리 필요` 목록으로 내려준다.
- 화면에는 `제품명 확인 필요` 경고 카드로 표시한다.
- 예: `허 브` → 제품명 정리 후보.

### 문제 6: 기간 선택이 년도뿐이라 질문에 답하기 어렵다

현재는 년도만 선택 가능하다.

부족한 질문:
- 이번 달만 볼 수 있나?
- 지난달과 비교할 수 있나?
- 특정 기간 행사/연휴 전후 매출을 볼 수 있나?
- 5월과 6월만 비교할 수 있나?

개선 방향:
- v1은 년도 유지 + 월 선택 보조를 추가한다.
- v2에서 `월별 보기`, `기간 비교`를 추가한다.
- 당장 우선은 “연간 화면 안에서 이번 달/전월 비교”를 먼저 넣는다.

### 문제 7: 일 평균 계산 기준이 설명되지 않는다

API는 `records.length`로 나누고 있다. 즉 기록이 있는 일수 기준이다.

문제:
- 직원/사장 입장에서는 “영업일 평균인지, 달력일 평균인지” 알 수 없다.
- 현재 2026년 데이터는 5~6월 기록 기준이라 연간 일 평균으로 오해될 수 있다.

개선 방향:
- 라벨을 `기록일 평균`으로 바꾼다.
- 보조 문구: `일일 운영 기록이 있는 날 기준`.
- API가 `recordedDays`를 내려주게 하고 화면에 `기록 61일 기준`처럼 표시한다.

### Task 2: API 파생 지표 구현

**Objective:** 기존 집계를 유지하면서 화면용 파생 지표를 추가한다.

**Files:**
- Modify: `apps/api/src/modules/sales-analysis/sales-analysis.routes.ts`

**Implementation notes:**
- `recordedDays = records.length`
- 월별 `averageTicket = count > 0 ? Math.round(sales / count) : 0`
- 월별 `hasRecord = count > 0 || sales > 0`
- 전월 비교는 바로 이전 월 판매액 기준으로 계산한다. 이전 월이 0이면 비율은 `null`, 금액 차이는 계산 가능.
- `lossRate = lossQty / (soldQty + lossQty + tastingQty)`; 분모가 0이면 `null`.
- 제품명 warning은 1차로 단순 룰부터 시작한다:
  - 연속 공백
  - 이름 앞/뒤 공백
  - 한글 사이 불필요한 공백 의심 예: `허 브`
- 0원/0건 채널은 화면에 굳이 리스트로 보이지 않도록 API에서 `channels`에는 유지하되 `dataWarnings`로도 알려준다. 화면에서는 숨김 처리 여부를 결정한다.

## 6. 리스크와 결정 필요 사항

1. 목표 설정 위치
   - 현재 목표는 `annualGoalNotice`의 sales category에 저장된다.
   - 화면에서 직접 목표를 수정할지, `관리`로 안내만 할지 결정 필요.
   - 추천: 이번 개선에서는 안내만 하고, 목표 수정은 관리 탭에 둔다.

2. 손실률 기준
   - `손실 / (판매 + 손실 + 시식)`으로 시작하는 것이 안전하다.
   - 시식은 의도된 제공일 수 있으므로 손실과 분리해 보여야 한다.

3. 제품명 정리
   - API에서 자동 보정까지 하면 위험하다.
   - 추천: 이번 단계는 경고만 표시하고, 실제 정리는 관리/일일 운영 import 정리에서 별도 진행.

4. 선결제 매출 포함 여부
   - 현재 매출 분석은 DailyOperationRecord의 POS + POS 외 기준이다.
   - 선결제 장부는 매출 인식 기준이 다를 수 있으므로 포함하지 않는다.
   - 추천: 별도 정의 전까지 선결제는 매출 분석에 포함하지 않는다.

## 7. 완료 기준

- 화면에서 `목표 0%` 오해가 사라진다.
- 사장이 첫 화면에서 “올해/이번 기록 기준 상황”을 한 문장으로 읽을 수 있다.
