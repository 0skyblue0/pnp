# 참조 대시보드 UI/UX 통일 설계

## 목적

`Docs/User_Send/카페 운영 관리 대시보드.zip`에서 추출한 Paul & Paulina 운영 대시보드의 디자인 시스템과 레이아웃을 현재 React 운영 시스템 전체에 적용한다. 데이터 모델, API, URL, 업무 흐름은 바꾸지 않고 시각 계층·공간 구조·반응형 경험을 통일한다.

## 범위

- 공통 앱 셸, 토큰, 버튼·폼·카드·표·상태 패턴
- 홈, 일일 운영, 매출 분석, 손님 반응, 예약, 단골손님, 선결제 장부, 관리, 알림
- 데스크톱/태블릿/모바일 레이아웃 및 키보드·감소 모션 접근성
- 단위 테스트와 5173 포트 헤드리스 브라우저 시각 검증

제외: API 변경, 데이터 마이그레이션, 신규 업무 기능, 참조 HTML의 정적 데이터를 실제 데이터로 추가하는 작업, 다크 모드.

## 디자인 시스템

### 토큰

- 표면: canvas `#eceae4`, page `#f4f0e9`, raised `#fbf8f3`, card `#ffffff`, table-muted `#faf7f1`.
- 텍스트: ink `#261e18`, secondary `#4a4136`, muted `#8a7f73`, subtle `#b3a794`.
- 브랜드: primary `#c8912f`, primary-strong `#a86e1f`, primary-soft `#efe7d7`, primary-wash `#fdf8ec`.
- 경계: border `#e7dfd3`, strong `#e0d7c8`, subtle `#f3ede2`.
- 상태: success `#3f7d4e`, warning `#c05621`, danger `#d9524a`, notice `#d95d39`, info `#3563a8`, comparison `#d9cfc0`.
- 간격: 4px 기반의 4, 8, 10, 12, 14, 16, 18, 20, 26px. 컨트롤/버튼/카드 반지름은 8/9/12px.
- 글꼴: UI는 Pretendard 계열, 브랜드만 Georgia/Noto Serif KR 계열. 페이지 제목 19px/800, 카드 제목 13.5px/800, 본문 13px, 라벨 11–11.5px, KPI 18–20px/800.
- 상호작용: 150–200ms `background-color`, `color`, `border-color`, `opacity`, `transform`만 사용. `prefers-reduced-motion`에서 전환을 제거한다.

### 접근성 규칙

- 일반 텍스트는 배경 대비 4.5:1 이상, 큰 텍스트/그래픽은 3:1 이상으로 유지한다.
- 버튼, 링크, 선택 가능한 탭은 visible focus ring을 유지하고 최소 44px 클릭 영역을 제공한다.
- 아이콘 단독 컨트롤은 `aria-label`, 현재 메뉴/탭은 선택 상태를 텍스트와 색으로 함께 전달한다.
- 경고·성공·알림은 색만 쓰지 않고 아이콘/문구/수치를 병행한다.
- 테이블이 모바일 폭을 넘을 경우 우선 카드형 행으로 전환하고, 불가피한 표만 명시적 가로 스크롤 컨테이너를 사용한다.

## 공통 구조

### 앱 셸

- 1024px 이상: 210px 코코아 사이드바와 나머지 작업면의 2열 구조. 사이드바는 브랜드, 아이콘+라벨의 주 메뉴, 알림 배지, 하단 사용자 요약을 갖는다.
- 768–1023px: 축소된 사이드바 또는 토글 가능한 내비게이션. 주요 콘텐츠는 2열/2×2 KPI까지 유지한다.
- 767px 이하: 헤더의 메뉴 버튼으로 내비게이션을 열고, 페이지 콘텐츠는 한 열로 정렬한다. 모든 폼/CTA는 44px 이상이다.
- 본문에는 page header(제목, 부제, 컨텍스트 액션)를 두며, 기본 데스크톱 content gutter는 26px이다.

### 공통 컴포넌트

- `PageHeader`: 제목/부제/우측 액션을 두며 모바일에서는 액션을 다음 줄로 감싼다.
- `Card`/`MetricCard`: 흰 표면 + 1px border + 12px radius. 표면 그림자는 모달/부유 패널에서만 사용한다.
- `Button`: primary(ink 배경), secondary(white+border), destructive(위험색)을 갖고 기존 loading/disabled 의미를 보존한다.
- `DataTable`: muted 헤더, 18px 좌우 여백, tabular 숫자, 합계 행을 지원한다.
- `StatusBadge`/`ScheduleTag`: 99px pill, 상태 텍스트를 항상 표시한다.
- `Field`: 항상 보이는 라벨, 오류/누락은 필드 근처의 안내와 primary-wash/warning 처리.

## 화면별 레이아웃

### 홈

- 헤더 아래 오늘의 업무·예약·손님 반응을 3개 상태 카드로 먼저 노출한다.
- 월 목표/누적/남은 목표/달성률을 전폭 카드와 진행 바로 제공한다.
- 공지·연간 일정·최근 알림을 3열 카드로 배치하고 모바일에서는 1열로 전환한다.

### 일일 운영

- 헤더에 날짜 이동, 임시저장 상태, 삭제·엑셀 미리보기·저장을 둔다.
- 미완성 데이터는 상단 경고 배너로 표시한다.
- 1024px 이상에서 환경·근무 정보(360px)와 채널별 매출(나머지)의 2열, 이어서 메모·점검과 제품 생산·판매의 2열을 둔다.
- 제품 표/엑셀 미리보기는 공통 DataTable/Card 규칙으로 통일한다.

### 매출 분석

- 헤더에 연도 선택과 목표 설정 진입 액션을 둔다.
- 핵심 KPI는 데스크톱 6열, 태블릿 2–3열, 모바일 1열이다.
- 목표 흐름은 전폭 카드, 채널/상위 제품/손실 제품/데이터 경고는 3열 보조 그리드로 둔다.
- 막대와 상태 수치는 비교·목표·경고 의미가 텍스트로도 읽히게 한다.

### 예약·손님 반응

- 예약은 넓은 일정/목록과 우측 예약 폼의 2열을 사용하며 모바일에서 폼은 목록 아래로 이동한다.
- 손님 반응은 입력 카드가 먼저, 필터·상세 기록 표가 아래에 온다.
- 상태/분류는 일관된 badge 및 행 강조를 사용한다.

### 단골손님·선결제 장부

- 단골손님은 저장된 목록(넓은 열) + 후보(보조 열) 구조다.
- 선결제 장부는 요약 KPI, 거래 내역, 고객/공동 선결제 상세의 계층을 명확히 한다.
- 긴 테이블은 모바일에서 제목+값 카드 행으로 표시한다.

### 관리·알림

- 관리의 내부 탭은 page header 아래의 명확한 탭 바로 정돈하며, 선택 상태를 골드 밑줄+텍스트로 전달한다.
- 알림은 중요도별 badge와 시간 메타를 두고, 읽지 않음은 색 외의 굵기/라벨로도 구분한다.

## 구현 구조

1. Tailwind 확장 토큰과 전역 컴포넌트 클래스를 새 시스템으로 정리한다.
2. `AppLayout`을 반응형 sidebar/drawer와 `PageHeader` 기반의 프레임으로 교체한다.
3. 기존 shared UI와 각 페이지의 카드·그리드·표 클래스를 토큰 기반으로 바꾼다.
4. 페이지별 DOM/상태/데이터 로딩의 의미를 유지하며 레이아웃만 재구성한다.

## 검증 기준

- 기존 전체 테스트, typecheck, lint가 통과한다.
- 레이아웃/핵심 상호작용을 검증하는 컴포넌트 테스트를 추가·갱신한다.
- 포트 5173의 기존 개발 서버를 재사용하거나 그 포트에서만 실행한다.
- Playwright 헤드리스로 1440px, 768px, 375px에서 홈·일일 운영·매출 분석·관리 화면을 확인한다.
- 가로 오버플로, focus visibility, 44px 컨트롤, 로딩/오류 피드백, reduced motion 스타일을 확인한다.
